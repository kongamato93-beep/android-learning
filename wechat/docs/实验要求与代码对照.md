## 一、第四个分页（「我」）是怎么创建出来的

整个链路分四层，**缺任何一层 Tab 都出不来**：

```
布局层   activity_main.xml   声明 4 个 Tab 按钮 + 1 个容器 FrameLayout
   ↓
索引层   MainActivity        TAB_IDS[] 定顺序，fragments[] 装实例，按下标一一对应
   ↓
创建层   MainActivity.onCreate()   new 出 4 个 Fragment 放进 fragments 列表
   ↓
切换层   MainActivity.selectTab()  用 FragmentTransaction 的 add / show / hide 控制显示
```

### 第 1 层：布局 —— `res/layout/activity_main.xml`

根布局是纵向 `LinearLayout`，三块：

| 区域 | 控件 | 关键属性 |
|---|---|---|
| 顶部标题栏 | `LinearLayout` + `tv_title` + `iv_action` | 高度 `toolbar_height`（48dp）|
| **中间容器** | `FrameLayout @+id/fl_container` | `layout_height="0dp"` + `layout_weight="1"` |
| 底部 Tab 栏 | `LinearLayout @+id/ll_tabs` | 水平，含 4 个子 `LinearLayout` |

中间容器写 `0dp + weight=1` 的含义是：**把标题栏和 Tab 栏占完之后剩下的高度全给它**。
所有 Fragment 的 View 都被塞进这一个 FrameLayout 里叠着，同一时刻只显示一个。

第四个 Tab 的按钮（就是最右边那个）：

```xml
<LinearLayout
    android:id="@+id/tab_me"
    android:layout_width="0dp"
    android:layout_height="match_parent"
    android:layout_weight="1"
    android:gravity="center"
    android:orientation="vertical">

    <ImageView
        android:layout_width="@dimen/tab_icon_size"
        android:layout_height="@dimen/tab_icon_size"
        app:srcCompat="@drawable/tab_icon_me"     <!-- 矢量图标，见评分点 8 -->
        app:tint="@color/tab_icon_tint" />

    <TextView
        style="@style/WeChatTabText"
        android:text="@string/tab_me" />
</LinearLayout>
```

四个 Tab 都是 `layout_width="0dp"` + `layout_weight="1"` → **等宽平分**屏幕宽度。

### 第 2 层：索引 —— `MainActivity` 的字段

```java
private static final int[] TAB_IDS = {
        R.id.tab_chat, R.id.tab_contacts, R.id.tab_discover, R.id.tab_me
};

private final List<View> tabViews = new ArrayList<>();      // 4 个 Tab 的整体按钮
private final List<Fragment> fragments = new ArrayList<>(); // 4 个分页内容
private final boolean[] fragmentsAdded = new boolean[TAB_IDS.length]; // 是否已 add 过
private int currentIndex = -1; // 当前在第几个 Tab，-1 表示还没选过
```

**这里是整个机制的关键：三个列表按下标一一对应。**
`TAB_IDS[3]` 是 `tab_me` 按钮，`fragments[3]` 就是 `MeFragment`。
点第 i 个按钮 → 显示第 i 个 Fragment，靠的就是这个下标一致。

### 第 3 层：创建 —— `onCreate()`

```java
chatListFragment = new ChatListFragment();
fragments.add(chatListFragment);
fragments.add(new ContactsFragment());
fragments.add(new DiscoverFragment());
fragments.add(new MeFragment());   // ← 第四个分页在这里创建
```

`new MeFragment()` 只是 **new 出一个对象**，还没有 View、也没有显示。
真正的 inflate 在 `MeFragment.onCreateView()` 里：

```java
return inflater.inflate(R.layout.fragment_me, container, false);
```

### 第 4 层：切换 —— `selectTab(int index)`

```java
FragmentTransaction ft = getSupportFragmentManager().beginTransaction();
for (int i = 0; i < fragments.size(); i++) {
    Fragment f = fragments.get(i);
    if (i == index) {
        if (fragmentsAdded[i]) {
            ft.show(f);          // 已经加过：直接显示
        } else {
            ft.add(R.id.fl_container, f);  // 第一次：add 进容器
            fragmentsAdded[i] = true;
        }
    } else if (fragmentsAdded[i]) {
        ft.hide(f);              // 其他的藏起来
    }
}
ft.commit();
```

配套的另外两件事：

```java
// 图标和文字的高亮：setSelected 会传给子 View，selector 收到状态就换图
tabViews.get(i).setSelected(i == index);

// 标题栏：必须先记 currentIndex 再刷新，否则标题是上一个 Tab 的名字（这里踩过 bug）
currentIndex = index;
updateUnread();
ivAction.setVisibility(index <= 1 ? View.VISIBLE : View.GONE); // 只有微信/通讯录有加号
```

### 为什么不用 ViewPager

| 方案 | 特点 |
|---|---|
| `ViewPager` + `FragmentPagerAdapter` | 支持左右滑，但微信的 Tab 本来就不能滑；而且默认会预加载、销毁相邻页 |
| **show / hide（本工程）** | 4 个 Fragment 常驻内存，切回来列表的**滚动位置、输入框内容都还在**，也不会重新查库 |

代价是 4 个页面同时占内存，但都是轻量列表，可以接受。

### 怎么验证这一步

```bash
adb shell am start -n com.example.wechat/.ui.main.MainActivity
adb shell uiautomator dump /sdcard/ui.xml && adb shell cat /sdcard/ui.xml
```
应该能看到 4 个 `resource-id="com.example.wechat:id/tab_xxx"`，且当前那个的 `selected="true"`。
再点第 4 个，标题栏文字应变成「我」（不带未读数）。

## 二、8 条评分点逐条对照

### 评分点 1｜用 AI 工具创建三分页界面程序（20 分）

要求 3 个分页，工程实际有 **4 个**，超额。

- `res/layout/activity_main.xml`：底部 `ll_tabs` 里 4 个子 `LinearLayout`
- `ui/main/MainActivity.java` → `TAB_IDS`、`onCreate()`：4 个 Tab + 4 个 Fragment

### 评分点 2｜手动添加第四分页，四页参照微信命名（10 分）

四个名字全部集中在 `res/values/strings.xml`，改文案只动这一处：

```xml
<string name="tab_chat">微信</string>
<string name="tab_contacts">通讯录</string>
<string name="tab_discover">发现</string>
<string name="tab_me">我</string>
```

用到它们的地方：
- `activity_main.xml`：每个 Tab 的 `android:text` 和 `contentDescription`
- `MainActivity` → `getTabTitle(int index)`：`switch` 按下标返回对应名字，给标题栏用

验证：依次点四个 Tab，标题栏应显示 `微信(N)` / `通讯录` / `发现` / `我`。

### 评分点 3｜微信页插入 ListView，显示 10 个好友姓名（20 分）

**布局**：`res/layout/fragment_chat_list.xml` —— 原来是 `RecyclerView`，已改成：

```xml
<ListView
    android:id="@+id/lv_conversations"
    android:layout_width="match_parent"
    android:layout_height="match_parent"
    android:divider="@null" />   <!-- 分隔线由行布局自己画，系统那条会错位 -->
```

**数据**：`db/DefaultDataSeed.java` → `contacts()`
内置 11 个联系人（张伟、李娜、王芳、刘强、陈晨、赵敏、周杰、妈妈、老爸、大学室友群、文件传输助手），
满足「10 个好友姓名」的要求；首次启动时由 `DatabaseInitializer` 写进 Room，只灌一次。

**装配**：`ui/main/ChatListFragment.java` → `onViewCreated()`

```java
adapter = new ConversationListAdapter(requireContext());
listView.setAdapter(adapter);
```

**刷新**：`refresh(keyword)` → `repository.getConversations()` → `adapter.setData(list, keyword)`，
列表为空时把 `tv_empty` 显示出来。

### 评分点 4｜自定义 ListView 每行显示头像 / 姓名 / 最近消息 / 时间（10 分）

**行布局**：`res/layout/item_conversation.xml`

| 控件 id | 类型 | 作用 |
|---|---|---|
| `iv_avatar` | ImageView | 头像，40dp，`centerCrop` |
| `tv_name` | TextView | 昵称 |
| `tv_last_message` | TextView | 最近一条消息 |
| `tv_time` | TextView | 时间 |
| `tv_unread` | TextView | 未读角标，无未读时 `GONE` |

**适配器**：`adapter/ConversationListAdapter.java`
继承 `BaseAdapter`（ListView 的自定义适配器只能从它继承，`RecyclerView.Adapter` 给 ListView 用不了），
四个抽象方法 `getCount / getItem / getItemId / getView` 全部实现。

**为什么必须这样写**：ListView 滑动时不会为每行新建 View，而是把滑出屏幕的行收回来当 `convertView` 传给你。
如果不用 ViewHolder，每滑一行就要 `findViewById` 四次，列表会卡。

```java
if (convertView == null) {
    convertView = inflater.inflate(R.layout.item_conversation, parent, false);
    holder = new ViewHolder(convertView);   // 只有第一次才找控件
    convertView.setTag(holder);             // 存进 View 的 tag
} else {
    holder = (ViewHolder) convertView.getTag();  // 以后直接取
}
```

### 评分点 5｜点击每行弹 Toast（10 分）

`ui/main/ChatListFragment.java` → `onViewCreated()` 里的 `setOnItemClickListener`

```java
Toast.makeText(requireContext(),
        getString(R.string.msg_click_conversation, displayName(conversation)),
        Toast.LENGTH_SHORT).show();

Intent intent = new Intent(requireContext(), ChatActivity.class);
intent.putExtra(ChatActivity.EXTRA_CONVERSATION_ID, conversation.getId());
startActivity(intent);
```

两个要点：

1. Toast 文字在 `strings.xml` 里是 `你点击了：%1$s`，`%1$s` 由 `displayName()` 填进去，
   取不到联系人时退回会话 id，避免 Toast 显示空白。
2. **Toast 是系统级窗口，不挂在 Activity 上**，所以先弹 Toast 再 `startActivity` 跳转，
   跳到聊天页之后 Toast 依然在屏幕上——截图时就会看到「聊天页 + Toast 同框」，
   这不是 bug，正好能证明点击生效了。

长按另有 `setOnItemLongClickListener` → 置顶 / 测试收消息，返回 `true` 表示事件已消费（不会再触发单击）。

### 评分点 6｜我页顶部用 ImageView + TextView 显示实验三登录用户的头像和姓名（10 分）

**布局**：`res/layout/fragment_me.xml` 顶部 `ll_profile`

```xml
<ImageView android:id="@+id/iv_avatar" ... />
<TextView  android:id="@+id/tv_name" ... />
<TextView  android:id="@+id/tv_wechat_id" ... />
```

**取值**：`ui/main/MeFragment.java` → `onViewCreated()`

```java
final LoginUserStore loginUser = new LoginUserStore(requireContext());
ivAvatar.setImageResource(loginUser.getAvatarRes());
tvName.setText(loginUser.getUsername());
tvWechatId.setText(getString(R.string.contact_wechat_id_prefix) + loginUser.getUsername());
```

**数据从哪来**：`data/LoginUserStore.java`
实验三（`com.example.myapplication`）把账号存在自己的 `SharedPreferences("users")` 里，演示账号 `5120244700`、
头像索引 `0`（对应 `avatar_1`）。但 **Android 7 之后两个 App 包名不同，跨包读不到对方的私有 SharedPreferences**，
所以这里把实验三的账号当默认值写进来，头像图片也复制成了 `login_avatar_1~3.jpg`（不覆盖本项目原有的 `avatar_1.jpg`）。

### 评分点 7｜我页自定义 ListView 显示七项（10 分）

**容器**：`res/layout/fragment_me.xml` 里的 `<ListView @+id/lv_entries>`

**七项数据**：`ui/main/MeFragment.java` → `buildEntries()`
服务 / 收藏 / 朋友圈 / 作品 / 小店与卡包 / 表情 / 设置（文案在 `strings.xml` 第 48-54 行）

**行布局**：`res/layout/item_me_entry.xml`（图标 + 标题 + 右侧说明 + 分隔线 + 分组间隔）

**适配器**：`adapter/MeEntryListAdapter.java`，同样走 `BaseAdapter` + `ViewHolder`

分组的实现方式值得单独说：

```java
holder.divider.setVisibility(item.isShowDivider() ? View.VISIBLE : View.GONE);
holder.groupSpace.setVisibility(item.isStartGroup() ? View.VISIBLE : View.GONE);
```

- `setStartGroup(true)`：在这一行前面加一段 8dp 的灰条 → 另起一组
- `setShowDivider(false)`：去掉这一行下面的线 → 本组最后一项

**为什么用可显隐的 View 而不是 margin**：ListView 的行是用 `AbsListView.LayoutParams` 量的，
这个 LayoutParams **不支持 margin 字段**，写了也会被忽略。所以分组间隔改成在行布局顶部放一个
`view_group_space`，需要时设成 `VISIBLE`，视觉上等价。

### 评分点 8｜底部导航用矢量图标（10 分）

三层结构：

1. **矢量图形**：`res/drawable/ic_tab_chat.xml`（还有 `_contacts` / `_discover` / `_me`）
   根节点是 `<vector>`，用 `pathData` 画图形，**不是 png**。任意分辨率缩放都不模糊。
2. **状态切换**：`res/drawable/tab_icon_chat.xml`
   是 `<selector>`，按 `state_selected` 在「实心图标」和「描边图标」之间切换，模拟微信选中/未选中。
3. **引用**：`activity_main.xml` 里 `app:srcCompat="@drawable/tab_icon_chat"` + `app:tint="@color/tab_icon_tint"`

配合 `MainActivity.selectTab()` 里的 `tabViews.get(i).setSelected(i == index)`：
`setSelected` 会往下传给子 View → ImageView 状态变化 → selector 自动换图 → 同时 tint 变色。

## 三、启动一次 App，代码是怎么跑的

```
LauncherActivity                     启动页/初始化
   ↓
MainActivity.onCreate()
   ├─ setContentView(activity_main)  加载布局
   ├─ InsetsHelper.applySystemBars()  状态栏/导航栏适配
   ├─ findViewById 标题栏 + 4 个 Tab
   └─ new 4 个 Fragment → selectTab(0)
        ↓
   selectTab(0)
        ├─ FragmentTransaction.add(fl_container, ChatListFragment)
        ├─ tab_chat.setSelected(true)
        └─ updateUnread()  → 标题栏「微信(N)」
                ↓
        ChatListFragment.onViewCreated()
                ├─ findViewById(lv_conversations)
                ├─ new ConversationListAdapter → setAdapter
                └─ refresh("") → repository.getConversations()
                        ↓
                adapter.getView() 每行：复用 ViewHolder → 填头像/昵称/消息/时间/未读
```

点第 4 个 Tab：`onClick` → 匹配到 `TAB_IDS[3]` → `selectTab(3)` → `hide` 前三个 / `show` MeFragment
→ `tab_me.setSelected(true)` → 标题栏「我」。
