## 总览：一个界面由三层拼起来

```
① 布局 XML      res/layout/xxx.xml          —— 画长什么样、控件叫什么 id
② Fragment/Activity  java/.../ui/main/      —— 找到控件、塞数据、监听点击
③ 适配器        java/.../adapter/           —— 负责"每一行长什么样、第几行显示第几条数据"
```

三者靠 **R.id** 串起来：XML 里写 `android:id="@+id/lv_conversations"`，编译后生成 `R.id.lv_conversations` 这个 int 常量，代码里 `findViewById(R.id.lv_conversations)` 就能拿到那个控件。

## 问题 1：适配器在哪里

**目录**：`app/src/main/java/com/example/wechat/adapter/`

| 文件 | 服务哪个页面 | 行布局 | 基类 |
|---|---|---|---|
| `ConversationListAdapter.java` | **微信页**会话列表 | `item_conversation.xml` | `BaseAdapter` ← 本次实验要求 |
| `MeEntryListAdapter.java` | **我页**七项列表 | `item_me_entry.xml` | `BaseAdapter` ← 本次实验要求 |
| `ContactsAdapter.java` | 通讯录 | — | `RecyclerView.Adapter` |
| `EntryAdapter.java` | 发现页 / 设置页 | — | `RecyclerView.Adapter` |
| `MessageAdapter.java` | 聊天窗口 | — | `RecyclerView.Adapter` |

**一眼区分的方法**：看 `extends` 后面跟的是什么。

- `extends BaseAdapter` → 给 **ListView** 用的，必须自己写 `getView()` 管复用
- `extends RecyclerView.Adapter<VH>` → 给 **RecyclerView** 用的，复用由系统管，你只写 `onBindViewHolder()`

本次实验第 3、4 条明确要求"自定义 ListView"，所以只有前两个达标，这也是之前把 RecyclerView 换掉的原因。

**适配器被谁 new 出来**：

```java
// ChatListFragment.java:58
adapter = new ConversationListAdapter(requireContext());
listView.setAdapter(adapter);
```

`setAdapter()` 是"装配"动作——ListView 从此知道：要多少行问 `getCount()`，第 n 行长什么样问 `getView(n, ...)`。

## 问题 2：图像是怎么显示到界面上的

### 三步走

**第 1 步：XML 里放一个 ImageView**

```xml
<!-- item_conversation.xml:18-24 -->
<ImageView
    android:id="@+id/iv_avatar"
    android:layout_width="@dimen/avatar_list"    <!-- 40dp -->
    android:layout_height="@dimen/avatar_list"
    android:scaleType="centerCrop"
    app:srcCompat="@drawable/avatar_default" />
```

**第 2 步：用 `app:srcCompat`，不要用 `android:src`**

这是最容易踩的坑。两个属性的区别：

| 属性 | 来源 | 能不能加载矢量图(vector) |
|---|---|---|
| `android:src` | 系统原生 | 低版本（<21）加载 vector 会直接崩 |
| `app:srcCompat` | AppCompat 库 | 兼容到 minSdk，本项目 minSdk=24 没问题 |

项目里所有 ImageView 统一用 `app:srcCompat`。

**第 3 步：代码里换图**

```java
holder.ivAvatar.setImageResource(R.drawable.avatar_default);
// 或者
AvatarLoader.load(context, holder.ivAvatar, peer.getAvatar());
```

`setImageResource(int resId)` 传的是 **R 文件里那个 int 常量**，不是文件名也不是路径。系统拿这个 int 去 resources 表里查到对应文件，解码 → 生成 Bitmap → 交给 ImageView 绘制。

### `scaleType="centerCrop"` 是干什么的

头像文件不一定是正方形。不加这个属性，图片会被拉变形。加了之后：

- 按比例缩放，直到短边填满 ImageView
- 超出的部分**从中心向两侧裁掉**

所以长方形图片也能填进 40dp 的正方形框里不变形。

### `app:tint` 染色：一套图变两种颜色

```xml
app:tint="@color/tab_icon_tint"
```

`res/color/tab_icon_tint.xml` 是个颜色选择器：

```xml
<selector>
    <item android:color="@color/wechat_green" android:state_selected="true" />
    <item android:color="@color/tab_text_normal" />   <!-- 灰色 -->
</selector>
```

**原理**：tint 会把图片里所有**不透明的像素**统一刷成指定颜色，透明像素保持透明。

所以底部图标只需要**一套白色描边的矢量图**，选中时刷成微信绿、未选中刷成灰色，**不用准备两套图片**。图标本身的形状（描边）不受影响，因为 `fillColor` 是透明的 `#00000000`，只有 `strokeColor` 是黑的，tint 只染那圈描边。

### 来源 B：我页顶部的大头像

### 来源 C：兜底灰头像

`R.drawable.avatar_default`，任何解析失败都用它。

### 关键的转换环节：AvatarLoader

```java
// util/AvatarLoader.java:26-35
private static int resolve(Context context, String avatar) {
    if (avatar == null || avatar.isEmpty()) {
        return R.drawable.avatar_default;
    }
    int resId = context.getResources()
            .getIdentifier(avatar, "drawable", context.getPackageName());
    if (resId == 0) {
        return R.drawable.avatar_default;
    }
    return resId;
}
```

`getIdentifier("avatar_1", "drawable", "com.example.wechat")` 是**运行时按名字反查资源 id**，查不到返回 0（不是抛异常，所以必须自己判 0）。

**为什么存字符串不存 int id**：解耦。
int id 是编译期常量，把 `R.drawable.avatar_1` 存进数据库，下次编译资源顺序一变 id 就失效了。存字符串的话，以后头像换成网络 URL（比如 `https://...`），只改 `AvatarLoader` 一个类的解析方式，数据库和所有界面都不用动。

## 问题 4 & 8：底部四个是用什么组件实现的

### 结论：没有用 BottomNavigationView，是手写 LinearLayout 嵌套

```
LinearLayout  ll_tabs                    ← 横向，高 56dp（tab_height），灰底
│   android:clipChildren="false"         ← 允许子 View 画到边界外
│
├── LinearLayout  tab_chat               ← 纵向，宽 0dp + weight=1
│   ├── FrameLayout  26dp×26dp           ← 包一层是为了放右上角的角标
│   │   ├── ImageView  app:srcCompat="@drawable/tab_icon_chat"
│   │   │              app:tint="@color/tab_icon_tint"
│   │   └── TextView   tv_tab_badge      ← 未读角标，marginTop=-5dp，画到图标外面
│   └── TextView      @string/tab_chat   ← "微信"
│
├── LinearLayout  tab_contacts           ← 同上
├── LinearLayout  tab_discover           ← 同上
└── LinearLayout  tab_me                 ← 同上
```

### 「四个等分」的实现原理

每个子 LinearLayout 都写：

```xml
android:layout_width="0dp"
android:layout_weight="1"
```

**weight（权重）机制**：父布局先给所有 `0dp` 的子 View 分配 0 宽度，然后把**剩余的全部空间**按 weight 比例分下去。四个都是 weight=1 → 各得 1/4。

为什么不直接写 `layout_width="25%"`？因为 weight 方式在屏幕旋转、分屏、不同密度下都不会出问题。

### 图标的两层结构

```
app:srcCompat = @drawable/tab_icon_chat   ← selector（状态选择器）
    ├── state_selected=true → @drawable/ic_tab_chat_filled   ← 实心矢量图
    └── 默认                 → @drawable/ic_tab_chat          ← 描边矢量图
```

```xml
<!-- drawable/tab_icon_chat.xml -->
<selector>
    <item android:drawable="@drawable/ic_tab_chat_filled" android:state_selected="true" />
    <item android:drawable="@drawable/ic_tab_chat" />
</selector>
```

`ic_tab_chat.xml` 是真正的矢量图：

```xml
<vector android:width="24dp" android:height="24dp"
        android:viewportWidth="24" android:viewportHeight="24">
    <path android:fillColor="#00000000"          <!-- 内部透明 -->
          android:pathData="M21,11.5 L21,16 ..."
          android:strokeColor="#FF000000"        <!-- 黑描边，靠 tint 变色 -->
          android:strokeWidth="1.8" />
</vector>
```

**矢量图 vs 位图**：矢量图存的是"怎么画"（路径坐标），缩放不失真，一个文件适配所有屏幕密度；位图（jpg/png）存的是像素点，放大就糊，要准备 hdpi/xhdpi/xxhdpi 好几套。这就是第 8 条评分点要求"矢量图标"的原因。

### 外层 `clipChildren="false"` 的作用

系统默认不允许子 View 画到父容器边界外。未读角标用负 margin（`marginTop="-5dp"`）往图标外面挪，不加这个属性会被**裁掉**。

## 问题 9：点击如何切换页面

### 完整链路

```
用户手指点 tab_me
   ↓
Android 把触摸事件派发给 tab_me 这个 View
   ↓
View 回调之前注册的 OnClickListener
   ↓
MainActivity.onClick(View v)          ← 因为 onCreate 里写过 tab.setOnClickListener(this)
   ↓
int id = v.getId();                    // 拿到 R.id.tab_me
   ↓
for 循环比对 TAB_IDS：发现 TAB_IDS[3] == R.id.tab_me  →  i = 3
   ↓
selectTab(3)
```

### selectTab 做了四件事

```java
// MainActivity.java:98-129
private void selectTab(int index) {
    // ① 已经是当前页就直接返回，避免重复提交事务
    if (index == currentIndex) return;

    // ② Fragment 显隐：目标 show（首次 add），其余 hide
    FragmentTransaction ft = getSupportFragmentManager().beginTransaction();
    for (int i = 0; i < fragments.size(); i++) {
        Fragment f = fragments.get(i);
        if (i == index) {
            if (fragmentsAdded[i]) ft.show(f);      // 已经加过 → 直接显示
            else { ft.add(R.id.fl_container, f);    // 第一次 → 加进容器
                   fragmentsAdded[i] = true; }
        } else if (fragmentsAdded[i]) {
            ft.hide(f);                             // 其余的藏起来
        }
    }
    ft.commit();

    // ③ 图标/文字高亮：setSelected 会向下递归传给所有子 View
    for (int i = 0; i < tabViews.size(); i++) {
        tabViews.get(i).setSelected(i == index);
    }

    // ④ 标题栏文字 + 加号显隐
    currentIndex = index;      // ← 必须先赋值
    updateUnread();            // ← 它内部要读 currentIndex
    ivAction.setVisibility(index <= 1 ? View.VISIBLE : View.GONE);
}
```

**④ 里的顺序是个真 bug 改过来的**：`updateUnread()` 内部 `getTabTitle(currentIndex)` 要用 currentIndex。如果先调 `updateUnread()` 再赋值，切到"我"页时标题栏还顶着上一个 Tab 的名字（显示"微信(3)"而不是"我"）。

### 为什么 add 一次、之后 show/hide

- `add()` 会把 Fragment 的 View 加进 `FrameLayout`，**只有第一次需要**
- 之后 `hide()` 只是把 View 设成 GONE，对象还在内存里

好处：切回来时列表滚动位置、搜索框文字、已加载的数据全都在，也不用重新查数据库。
代价：四个 Fragment 同时在内存里。但它们都是轻量列表，可以接受。

### 为什么不用 ViewPager

1. 微信的 Tab 本来就不能左右滑动，用不上 ViewPager 的手势
2. ViewPager 默认会预加载/销毁页面，切回来要重建 View，列表位置会丢

### 三个列表的下标对应关系（核心设计）

```java
private static final int[] TAB_IDS = {R.id.tab_chat, R.id.tab_contacts, R.id.tab_discover, R.id.tab_me};
private final List<View>      tabViews  = new ArrayList<>();  // 4 个按钮
private final List<Fragment>  fragments = new ArrayList<>();  // 4 个页面内容
private final boolean[]       fragmentsAdded = new boolean[4];
```

**三个数组按下标一一对应**：`TAB_IDS[3]` 是"我"的按钮，`fragments[3]` 就是 `MeFragment`。
点第 i 个按钮 → 显示第 i 个 Fragment，全靠这个下标。

想加第五个 Tab：在 XML 复制一个 `LinearLayout`，在 `TAB_IDS` 加一行，在 `fragments.add()` 加一个 —— **三处都要加，且顺序必须一致**，否则点了"发现"会跳到"我"。

## 问题 5：跳转是怎么实现的

### 三行固定套路

```java
Intent intent = new Intent(requireContext(), ChatActivity.class);      // ① 从哪到哪
intent.putExtra(ChatActivity.EXTRA_CONVERSATION_ID, conversation.getId()); // ② 带参数
startActivity(intent);                                                  // ③ 发起跳转
```

### Intent 是什么

一个"意图描述对象"，告诉系统"我要启动哪个 Activity"。系统查 AndroidManifest 里注册的 Activity，创建实例，把它推到栈顶。

### putExtra 传参

本质是往 Intent 内部的 Bundle（一个 key-value Map）里塞数据：

```java
// 发送方
intent.putExtra("conversation_id", "conv_1");

// 接收方 ChatActivity.onCreate()
String id = getIntent().getStringExtra("conversation_id");
```

**为什么要定义成常量** `ChatActivity.EXTRA_CONVERSATION_ID`：
手写字符串两边容易打错，错了不报错只会取到 null。定义成常量后写错编译就过不去。

### 工程里三处跳转

| 起点 | 终点 | 传什么 |
|---|---|---|
| 微信页点会话行 | `ChatActivity` | 会话 id |
| 通讯录点联系人 | `ContactDetailActivity` | 联系人 id |
| 我页点「设置」 | `SettingsActivity` | 无 |

### 我页的跳转带了个判断

```java
// MeFragment.java:72-75
if (getString(R.string.me_settings).equals(item.getTitle())) {
    startActivity(new Intent(requireContext(), SettingsActivity.class));

}
// 其余六项只弹 Toast「功能待实现」
```

七项里只有「设置」有真实页面，其余六项点了只弹 Toast。这是刻意保留的，等后面逐个补页面。

## 问题 7：微信页每一行——布局在哪，头像/名字/时间怎么传进去的

### 布局：`res/layout/item_conversation.xml`

```
LinearLayout（纵向，根）
│   android:background="?attr/selectableItemBackground"   ← 点击水波纹
│
├── LinearLayout  ll_conversation_content（横向，高 64dp）
│   │   android:gravity="center_vertical"      ← 里面所有内容垂直居中
│   │   android:paddingStart/End="12dp"
│   │
│   ├── ImageView  iv_avatar                          ← 【头像】40dp，centerCrop
│   │
│   ├── LinearLayout（纵向，宽 0dp + weight=1）        ← 【吃掉中间所有剩余宽度】
│   │   ├── TextView  tv_name                          ← 【名字】16sp #181818 单行省略号
│   │   └── TextView  tv_last_message                  ← 【最近消息】14sp #7F7F7F
│   │
│   └── LinearLayout（纵向，wrap_content，gravity=end）← 【靠右】
│       ├── TextView  tv_time                          ← 【时间】12sp #B2B2B2
│       └── TextView  tv_unread                        ← 【未读角标】默认 gone
│
└── View  分隔线                                        ← 高 0.5dp，左边留 64dp
```

**为什么中间那层要 `0dp + weight=1`**：
名字可能很长（"文件传输助手"），时间总是很短。如果中间写 `wrap_content`，长名字就会把时间挤出屏幕。用 weight=1 后，中间区域"吃掉除了头像和时间之外的所有宽度"，名字再长也只会被省略号截断，时间永远贴在右边。

### 数据传进去的完整链路（重点）

这是最容易搞混的地方。数据不是"推"给界面的，是"被要"出来的。

```
① 首次启动
   db/DatabaseInitializer → db/DefaultDataSeed.contacts()/conversations()
   → 写进 Room 数据库（app 私有 SQLite）

② Fragment 要数据
   ChatListFragment.refresh(keyword)
       List<Conversation> list = repository.getConversations();
       // 内部：db/RoomDataRepository.getConversations()
       //      → sortConversations() 排序：置顶的排最前，其余按时间倒序

③ 交给适配器
   adapter.setData(list, keyword);
       → 按关键字过滤（匹配昵称或最后一条消息）
       → 结果存进适配器内部的 data 列表
       → notifyDataSetChanged();   ← 只是"广播：数据变了"

④ ListView 主动来要行
   系统计算屏幕上能放几行，对可见的每一行回调：
       getView(position, convertView, parent)

⑤ 适配器填数据（ConversationListAdapter.getView）
       Conversation c = getItem(position);            // 取第 position 条会话
       Contact peer = repository.getContact(c.getPeerId());  // 按 id 查联系人
       holder.tvName.setText(peer.getName());          // ← 名字
       AvatarLoader.load(ctx, holder.ivAvatar, peer.getAvatar()); // ← 头像
       holder.tvLastMessage.setText(c.getLastMessage());// ← 最近消息
       holder.tvTime.setText(TimeUtil.formatListTime(c.getLastTimeMillis())); // ← 时间
       holder.tvUnread...                              // ← 未读角标
```

### 关键点：适配器不"推"数据，而是"等 ListView 来要"

`notifyDataSetChanged()` **不会**立刻刷新界面，它只是打个标记说"数据变了"。
真正画图的是 ListView：它自己算出屏幕上需要哪几行，然后一行一行回调 `getView()` 来要 View。

所以 100 条数据在屏幕上只会有 8~10 个行 View 存在，滑出屏幕的行会被回收成 `convertView` 重复利用。这就是为什么必须写 ViewHolder —— 避免每次都 `findViewById()`。

**名字和头像的来源不一样**，这点要注意：

| 显示内容 | 数据来源 | 代码 |
|---|---|---|
| 名字 | `Contact.getName()` | `repository.getContact(peerId)` 按 id 现查 |
| 头像 | `Contact.getAvatar()`（字符串） | `AvatarLoader` 解析成资源 id |
| 最近消息 | `Conversation.getLastMessage()` | 会话对象自带 |
| 时间 | `Conversation.getLastTimeMillis()` | 经 `TimeUtil.formatListTime()` 格式化 |

**为什么名字要"现查"而不是在适配器里缓存 Contact 对象**：
如果缓存了对象，联系人在别处改了名字，列表不会自动更新。现查虽然每次多一次 Map 查找，但保证了数据一致。`Conversation` 里只存 `peerId` 就是为这个。

### 时间的格式化

```java
// util/TimeUtil.java:22-34
public static String formatListTime(long millis) {
    int dayOffset = dayOffset(millis);      // 距今几天（按自然日算）
    if (dayOffset == 0) return new SimpleDateFormat("HH:mm", Locale.CHINA).format(new Date(millis));
    if (dayOffset == 1) return "昨天";
    if (dayOffset < 7)  return weekday(millis);   // 星期一...
    return new SimpleDateFormat("M月d日", Locale.CHINA).format(new Date(millis));
}
```

跟微信一致：今天的显示 `14:30`，昨天的显示 `昨天`，一周内显示 `星期三`，更早显示 `10月8日`。

## 补充：点击行弹 Toast + 跳转

```java
// ChatListFragment.java:62-77
listView.setOnItemClickListener(new AdapterView.OnItemClickListener() {
    @Override
    public void onItemClick(AdapterView<?> parent, View view, int position, long id) {
        Conversation conversation = adapter.getItem(position);   // ← 用 position 取数据
        if (conversation == null) return;

        Toast.makeText(requireContext(),
                getString(R.string.msg_click_conversation, displayName(conversation)),
                Toast.LENGTH_SHORT).show();

        Intent intent = new Intent(requireContext(), ChatActivity.class);
        intent.putExtra(ChatActivity.EXTRA_CONVERSATION_ID, conversation.getId());
        startActivity(intent);
    }
});
```

三个要点：

1. **`position` 是系统给你的**，拿它调 `adapter.getItem(position)` 取数据。
   **不要**去 `((TextView) view.findViewById(R.id.tv_name)).getText()` 反解文字 —— 行 View 是复用的，而且显示的是截断后的文本，拿不到完整数据。

2. **Toast 先弹再跳转**：Toast 是系统级窗口，不挂在 Activity 上。跳到聊天页之后 Toast 还在屏幕上，所以截图能拍到"聊天页 + Toast 同框"。这不是 bug，反而证明点击生效了。

3. **长按返回 `true`**：

```java
listView.setOnItemLongClickListener(new AdapterView.OnItemLongClickListener() {
    @Override
    public boolean onItemLongClick(...) {
        showConversationMenu(view, conversation);
        return true;    // ← 吃掉事件，避免长按后手指抬起又触发一次单击
    }
});
```
