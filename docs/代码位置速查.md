## 2. 图片是「怎么显示到界面上」的？

三步，缺一不可：

**第 1 步：布局里放一个 ImageView**

`res/layout/item_conversation.xml`：

```xml
<ImageView
    android:id="@+id/iv_avatar"
    android:layout_width="@dimen/avatar_list"
    android:layout_height="@dimen/avatar_list"
    android:scaleType="centerCrop"
    app:srcCompat="@drawable/avatar_default" />
```

两个属性要留意：

- `app:srcCompat`：不是 `android:src`。AppCompat 提供的属性，**能正确加载 vector 矢量图**，
  用 `android:src` 在低版本上加载 vector 会崩。
- `scaleType="centerCrop"`：图片比例和控件不一致时，按短边裁切填满，头像不会被拉扁。

**第 2 步：代码里把资源 id 塞进去**

```java
imageView.setImageResource(R.drawable.login_avatar_1);
```

`R.drawable.xxx` 是编译期生成的 int 常量，系统拿它去 `res/drawable` 找同名文件，解码后画到控件上。

**第 3 步：想改颜色就加 tint**

```xml
app:tint="@color/tab_icon_tint"
```

`tint` 是给图片「染色」，一张白底图标靠它变成灰/绿，底部 Tab 选中变色就是这么做的——
**不用准备两套图片**。

## 3. 头像是从哪里来的？

三条来源，按优先级：

### ① 会话行头像（微信页）
源头在 `db/DefaultDataSeed.java` → `contacts()`：

```java
list.add(contact("c_zhangwei", "张伟", "avatar_1", ...));
list.add(contact("c_lina", "李娜", "avatar_2", ...));
...
```

第三列 `"avatar_1"` 就是头像字段，对应 `res/drawable/avatar_1.jpg`（共 6 张，循环复用）。
首次启动时 `DatabaseInitializer` 把这份种子数据写进 Room，**只灌一次**，之后从数据库读。

### ② 我页头像（实验三的账号）
`data/LoginUserStore.java`：

```java
private static final String DEFAULT_USERNAME = "5120244700";
private static final int DEFAULT_AVATAR_INDEX = 0;   // 0 → login_avatar_1

private static final int[] AVATAR_RES = {
        R.drawable.login_avatar_1,
        R.drawable.login_avatar_2,
        R.drawable.login_avatar_3
};
```

图片是 `res/drawable/login_avatar_1~3.jpg`，**从实验三工程复制过来的**。
之所以叫 `login_` 前缀：本项目原本就有 `avatar_1.jpg`，直接复制会覆盖，改名避开。

### ③ 兜底灰头像
`R.drawable.avatar_default`，任何解析失败的情况都用它，保证界面不出现空白。

### 从「字符串」到「图片」的关键一步

数据库里存的是字符串 `"avatar_1"`，而 `setImageResource()` 要的是 int 资源 id。
转换由 `util/AvatarLoader.java` 完成：

```java
int resId = context.getResources()
        .getIdentifier(avatar, "drawable", context.getPackageName());
if (resId == 0) {
    return R.drawable.avatar_default;   // 名字对不上就用默认图
}
return resId;
```

**为什么这么绕**：存字符串等于「解耦」。以后头像换成 URL 或者用户相册里的图，
只要改 `AvatarLoader` 这一个类的解析方式，数据库和所有界面都不用动。

## 4. 底部导航：四个是用什么组件实现的？

**没有用 `BottomNavigationView`**，是手写的：

```xml
<LinearLayout
    android:id="@+id/ll_tabs"
    android:layout_width="match_parent"
    android:layout_height="@dimen/tab_height"
    android:background="@color/tab_bg"
    android:clipChildren="false"
    android:orientation="horizontal">

    <LinearLayout android:id="@+id/tab_chat" ... android:orientation="vertical">
        <ImageView app:srcCompat="@drawable/tab_icon_chat" app:tint="@color/tab_icon_tint" />
        <TextView android:text="@string/tab_chat" />
    </LinearLayout>

    <!-- tab_contacts / tab_discover / tab_me 结构完全一样 -->
</LinearLayout>
```

组件清单：

| 组件 | 作用 |
|---|---|
| `LinearLayout`（横向） | 外层容器，装四个 Tab |
| `LinearLayout`（纵向）×4 | 每个 Tab：上面图标、下面文字 |
| `ImageView` ×4 | Tab 图标 |
| `TextView` ×4 | Tab 文字 |

**「四个等分」靠两个属性**：

```xml
android:layout_width="0dp"
android:layout_weight="1"
```

`0dp` 的意思是"宽度先不按内容算"，`weight=1` 意思是"剩下的空间按权重分"，
四个都是 1 → 每人 1/4。想加第五个 Tab，复制一份改成 5 个 weight=1 即可。

一个容易忽略的细节：外层加了 `android:clipChildren="false"`。
因为"微信" Tab 右上角有个未读红点角标，它要画到图标边界**外面**，
不加这个属性，超出父容器边界的部分会被裁掉。

文件：`res/layout/activity_main.xml`，底部 Tab 栏那一段。

## 5. 点击是怎么切换页面的？

完整链路（以点第 4 个「我」为例）：

```
手指点 tab_me (LinearLayout)
   ↓ 系统回调 OnClickListener.onClick(v)
MainActivity.onClick(v)
   ↓ int id = v.getId();         拿到被点控件的 id
   ↓ 拿 id 去 TAB_IDS 里逐个比对
   ↓ TAB_IDS[3] == R.id.tab_me  匹配上，i = 3
selectTab(3)
   ├─ FragmentTransaction：前三个 hide，第 4 个首次 add（之后 show）
   ├─ tabViews.get(i).setSelected(i == 3)   → 图标/文字高亮
   ├─ currentIndex = 3                      → 先记下标
   ├─ updateUnread()                        → 再刷标题栏「我」
   └─ ivAction.setVisibility(GONE)          → 「我」页没有右上角加号
```

关键代码 —— `MainActivity`：

```java
public void onClick(View v) {
    int id = v.getId();
    if (id == R.id.iv_action) { showActionMenu(); return; }
    // 用 id 反查下标：TAB_IDS 的顺序就是 Tab 的顺序
    for (int i = 0; i < TAB_IDS.length; i++) {
        if (TAB_IDS[i] == id) { selectTab(i); return; }
    }
}
```

监听器在哪绑的 —— `MainActivity.onCreate()`：

```java
for (int id : TAB_IDS) {
    View tab = findViewById(id);
    tab.setOnClickListener(this);   // Activity 自己当监听器
    tabViews.add(tab);              // 存起来，切换时统一改选中态
}
```

`tabViews` 这个列表是必需的：`selectTab()` 里要对**所有** Tab 调 `setSelected`，
保证只有当前那个是亮的，其他都灭掉。

**为什么不用 `setOnItemSelectedListener`**：那是 `BottomNavigationView` 的 API，
我们用的是普通 `LinearLayout`，只能走 `View.OnClickListener` + `getId()` 反查。

## 6. 跳转是怎么实现的？

Android 的页面跳转固定三行：

```java
Intent intent = new Intent(requireContext(), 目标Activity.class);
intent.putExtra("键", 值);        // 可选：带参数过去
startActivity(intent);
```

工程里一共三处跳转：

| 起点 | 终点 | 代码位置 |
|---|---|---|
| 微信页点某一行 | `ChatActivity`（聊天窗口）| `ChatListFragment` → `setOnItemClickListener` |
| 通讯录点联系人 | `ContactDetailActivity`（联系人详情）| `ContactsFragment` → `onContactClick` |
| 我页点「设置」 | `SettingsActivity`（设置页）| `MeFragment` → `setOnItemClickListener` |

会话跳转那处完整长这样：

```java
// 先让用户看到点到了谁
Toast.makeText(requireContext(),
        getString(R.string.msg_click_conversation, displayName(conversation)),
        Toast.LENGTH_SHORT).show();

// 再带着会话 id 跳到聊天页
Intent intent = new Intent(requireContext(), ChatActivity.class);
intent.putExtra(ChatActivity.EXTRA_CONVERSATION_ID, conversation.getId());
startActivity(intent);
```

`putExtra` 传的是会话 id，聊天页 `getIntent().getStringExtra(...)` 取出来，才知道要加载哪个会话的消息。

其余六项（服务/收藏/朋友圈/作品/小店与卡包/表情）只弹 Toast，因为二级页面还没做。

## 8. 「微信」页每一行的布局在哪？头像/名字/时间是怎么传进去的？

### 布局：`res/layout/item_conversation.xml`

```
LinearLayout（纵向，根，点击有水波纹）
├── LinearLayout  ll_conversation_content（横向，行高 = conversation_item_height）
│   ├── ImageView  iv_avatar          ← 头像（40dp）
│   ├── LinearLayout（纵向，weight=1，吃掉中间所有剩余宽度）
│   │   ├── TextView tv_name          ← 昵称
│   │   └── TextView tv_last_message  ← 最近一条消息
│   └── LinearLayout（纵向，靠右）
│       ├── TextView tv_time          ← 时间
│       └── TextView tv_unread        ← 未读角标（无未读时 GONE）
└── View                              ← 分隔线（左侧留 divider_start 缩进）
```

### 数据是怎么"传进去"的

**核心认知：适配器不是把数据推给界面，而是等 ListView 来要。**

```
① 数据库      Room：ConversationEntity / ContactEntity
                    ▲
                    │ 首次启动由 DatabaseInitializer 灌入 DefaultDataSeed
② 仓库层      RoomDataRepository.getConversations()
                    → 把 Entity 转成 Model（Conversation / Contact）
③ Fragment    ChatListFragment.refresh(keyword)
                    → 拿到 List<Conversation>
④ 适配器      ConversationListAdapter.setData(list, keyword)
                    → 按关键字过滤 → 存进内部字段 data
                    → notifyDataSetChanged()   ← 只是"通知变了"
⑤ 回调        ListView 对当前屏幕可见的每一行回调
              getView(position, convertView, parent)
⑥ 绑定        取出数据 → 一个个塞进控件
              holder.tvName.setText(peer.getName())
              AvatarLoader.load(ctx, holder.ivAvatar, peer.getAvatar())
              holder.tvTime.setText(TimeUtil.formatListTime(...))
```

对应到代码 —— `ConversationListAdapter.getView()`：

```java
// 第 1 步：行复用（见第 9 节）
ViewHolder holder;
if (convertView == null) {
    convertView = inflater.inflate(R.layout.item_conversation, parent, false);
    holder = new ViewHolder(convertView);
    convertView.setTag(holder);
} else {
    holder = (ViewHolder) convertView.getTag();
}

// 第 2 步：取这一行的数据
Conversation conversation = getItem(position);
Contact peer = repository.getContact(conversation.getPeerId());

// 第 3 步：填进控件
holder.tvName.setText(peer.getName());                       // 名字
AvatarLoader.load(ctx, holder.ivAvatar, peer.getAvatar());   // 头像
holder.tvLastMessage.setText(conversation.getLastMessage());  // 最近消息
holder.tvTime.setText(TimeUtil.formatListTime(
        conversation.getLastTimeMillis()));                   // 时间
```

注意头像和名字的**来源不同**：

| 显示内容 | 数据来自 | 说明 |
|---|---|---|
| 名字 | `Contact.getName()` | 按 `peerId` 现查，不缓存对象，联系人改了列表能跟着变 |
| 头像 | `Contact.getAvatar()` → `AvatarLoader` | 存的是 drawable 名字符串，运行时解析成资源 id |
| 最近消息 / 时间 / 未读 | `Conversation` 自己的字段 | 会话表自带 |
| 背景色 | `conversation.isPinned()` | 置顶会话换浅灰底 |

`ViewHolder` 的作用在第 9 节说。

## 9. 点击某一行：弹 Toast + 跳转，是怎么触发的？

ListView 用的是**行点击监听**，不是给每个控件单独设监听：

```java
listView.setOnItemClickListener(new AdapterView.OnItemClickListener() {
    @Override
    public void onItemClick(AdapterView<?> parent, View view, int position, long id) {
        Conversation conversation = adapter.getItem(position);  // 直接用 position 取数据
        Toast.makeText(...).show();
        startActivity(...);
    }
});
```

`position` 是系统给你的行号，拿它调 `adapter.getItem(position)` 就能拿到这一行对应的数据对象——
**这是 ListView 传数据的正路**，不要去解析 View 上的文字。

长按另有一个监听：

```java
listView.setOnItemLongClickListener(...);   // 置顶 / 测试收消息
```

里面 `return true` 表示"事件我吃掉了"，这样长按之后不会再误触发单击。

## 10. 行复用（ViewHolder）到底解决了什么

`item_conversation.xml` 里有 5 个控件，每行显示都要 `findViewById` 5 次。
一屏 8 行，滑过 100 行就是 500 次查找 —— 会掉帧。

ListView 的做法：**滑出屏幕的行不销毁，收回来当 `convertView` 传给你**。
你只要把里面的控件引用缓存下来就行，缓存放在 View 自带的 `tag` 里：

```java
private static class ViewHolder {
    View llContent;
    ImageView ivAvatar;
    TextView tvName;
    TextView tvLastMessage;
    TextView tvTime;
    TextView tvUnread;

    ViewHolder(View itemView) {
        // findViewById 只在这里做一次
        llContent = itemView.findViewById(R.id.ll_conversation_content);
        ivAvatar = itemView.findViewById(R.id.iv_avatar);
        ...
    }
}
```

判断逻辑就一句：`convertView == null` 说明**屏幕上还没有可复用的行**（首次显示或缓存不够），
这时才 inflate + 建 ViewHolder；否则直接 `getTag()` 拿出来用。

**常见坑**：有人会漏掉 else 分支，每次都重新 inflate——那样 ViewHolder 就白写了。
